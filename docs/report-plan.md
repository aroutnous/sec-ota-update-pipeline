# Plan du rapport technique (R4)

Chaque membre redige la section de son module des qu'il fonctionne.

1. Contexte, probleme et modele d'attaquant
2. Conception : trois verifications (authentique, integre, recente), choix version + hash signes
3. Implementation : cles et paquet (R1), serveur (R1), client et log (R2)
4. Methodologie des tests : harnais, test de controle, proxy MITM (R3, R4)
5. Resultats des 5 attaques (fiches) et test de controle
6. Echecs rencontres et analyse honnete (a partir de `journal-echecs.md`)
7. Limites (deni de service, TLS hors perimetre) et pistes
8. Reflexion specifique de l'equipe
